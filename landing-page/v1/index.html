Why DataOrbyt

Your data is spread across tools. Your decisions shouldn’t be.

  • Metrics live in separate products and spreadsheets, each with its own number.
  • Meetings turn into reconciling definitions instead of deciding what to do.
  • Dashboards are slow to build, easy to break, and awkward to share.
  • Product experiments rarely connect back to revenue and retention.

Trusted metrics with dbt

Make every team use the same definition.

Keep transformations, tests, and metric logic organized in dbt. Help people understand where a metric comes from before they make a decision with it.

  • Lineage from source table to dashboard
  • Tests and freshness visible next to the number
  • New metrics go through review before anyone can chart them

dbt standardizes transformations. It doesn’t make warehouse queries free or tune their cost by itself.

Cost and governance

Useful answers without uncontrolled warehouse queries.

Every chart, alert and assistant request goes through one governed query layer. These controls are in the current preview build, which runs against demo data. Real warehouse adapters are in development.

  • Shared metric definitions

    Charts, alerts and MCP tools query approved catalog metrics, not ad-hoc SQL.

  • Pre-aggregated, incremental models

    The dbt starter favors daily marts and incremental models for routine dashboards.

  • Cached dashboard results

    Identical queries reuse a cached result until the underlying data changes.

  • Query limits and usage

    Row limits, timeouts, range caps and a per-project scan budget, with usage by dashboard.

  • Permissions and audit history

    Project-scoped API tokens and an audit trail of changes and MCP tool calls.

We don’t promise a specific reduction in warehouse spend. These controls make query cost visible and bounded.

Privacy & security

Your analytics should respect your data boundaries.

These are the principles DataOrbyt is built around. Each one is marked with its status today. We don’t claim certifications or compliance programs we haven’t completed.

  • Product principle

    Customer-authorized sources only

    DataOrbyt connects to the sources you add, with the least-privilege access each connector asks for.

  • In preview build

    Secrets stay on the server

    Credentials are sent only to the server and never kept in the browser. API tokens are shown once and stored hashed.

  • Partly on roadmap

    Scoped by workspace and project

    API tokens are already project-scoped. Per-user sign-in and role enforcement are still on the roadmap.

  • In preview build

    Demo data is always labelled

    Seeded and simulated data carries a visible “Demo data” label so it can’t be mistaken for your numbers.
