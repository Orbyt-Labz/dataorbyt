Keep dashboards useful and queries controlled.

Every chart, alert and Claude request goes through the same controlled query layer. In the current preview these controls run against demo data; real warehouse connections are in development.

  • In preview

    Shared, approved metrics

    Charts and requests use defined metrics, not one-off queries.

  • In preview

    Cached results

    Repeated dashboard views reuse results until the data changes.

  • Design approach

    Pre-aggregated models

    Daily summary tables where appropriate, so common views stay light.

  • In preview

    Limits and visibility

    Query limits, a daily budget per project, and usage you can see.

We don’t promise a specific reduction in warehouse costs, and dbt on its own doesn’t make queries cheap. These controls make query use visible and bounded.

Your analytics should respect your data boundaries.

These are the principles DataOrbyt is built around, each marked with its status today. We don’t claim certifications or compliance programs we haven’t completed.

  • Design principle

    Customer-authorized access

    DataOrbyt only connects to the sources you add, with the least access each one needs.

  • In preview

    Secrets stay on the server

    Credentials are handled on the server and never kept in the browser. Access tokens are shown once and stored hashed.

  • Partly on roadmap

    Project-scoped access

    Access tokens are limited to specific projects today. Per-user sign-in and roles are on the roadmap.

  • In preview

    Demo data is labelled

    Sample and simulated data always carries a visible “Demo data” label.
